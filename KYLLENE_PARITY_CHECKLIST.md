# Kyllene → Hermes Webapp parity checklist

**Scope:** User-visible, implemented Kyllene features compared with the browser-hosted Hermes Desktop renderer. This is a functional parity checklist, not a port of Kyllene's Kotlin/Android implementation. Android-only system APIs, Wear OS, APK distribution, and native OS integrations are listed separately rather than treated as webapp requirements. Kyllene roadmap items still unchecked are not counted as shipped parity requirements; they are called out where relevant.

**Kyllene baseline:** official [`README.md`](https://github.com/Giton22/kyllene/blob/master/README.md) and [`docs/ROADMAP.md`](https://github.com/Giton22/kyllene/blob/master/docs/ROADMAP.md), checked 2026-11-07. **Hermes baseline:** the local `hermes-agent-fork-kyllene-webapp-parity` checkout and the [Hermes Webapp docs](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/desktop.md). Hermes describes the Webapp as the Desktop renderer served in a browser; native-only Electron APIs may still be unavailable. “In code” is not the same as deployed or live-tested on Android/Zen.

## Status key

- **DONE — shared code:** the capability is present in the shared Hermes Desktop/Webapp code path; still needs live acceptance where browser permissions or gateway versions matter.
- **PARTIAL:** some of the feature exists, but a material Kyllene behavior is absent, incorrect, local-only, or unverified.
- **MISSING:** no equivalent was found in the audited Webapp paths, or the current behavior contradicts the desired behavior.
- **NATIVE / N/A:** Kyllene capability depends on Android, Wear OS, or its native distribution model; it is not a direct web feature.

| Phone calling | Kyllene's optional ring-on-approval/clarify feature; answer the request by voice, with a normal notification if unanswered | **MISSING as Webapp integration** | Kyllene rings when an approval/question is pending in a chat out of sight; the user can answer by voice. | Phone calling | Agent rings for any other explicitly critical/major update | **MISSING as a policy** | A separate Hermes `phone_call_me` tool can ring the user from this agent runtime, but there is no defined severity policy or event-triggered integration. | Mobile shell | Installable PWA, home-screen shortcut, share text/link into Hermes | **PARTIAL — local worktree** | Manifest, icons, share target and integration code exist locally but are uncommitted and not deployment-verified. The service worker does not provide offline caching or push. |

| Platform | Responsive phone/tablet/foldable layout and mobile interaction polish | **PARTIAL — acceptance needed** | Webapp is accessible on phone/Zen, but no full Kyllene-equivalent mobile usability pass is recorded. |
| Kyllene roadmap | Wake word, message reactions, bot avatar uploads, ask-a-bot-by-voice, bot quick replies in notifications | **NOT SHIPPED IN KYLLENE** | These roadmap items are unchecked; they are not counted as existing parity gaps. Revisit if they ship or become explicit Hermes requirements. |
| Delivery | Stable deployment/update path across devices | **PARTIAL — not verified here** | Local changes are not necessarily committed or deployed to the instance Jagan uses. Confirm the deployed build/version before calling any local-only feature delivered. |

## Highest-priority gaps

1. **Fix smart follow-up click behavior:** populate the active composer draft, preserve the user's ability to edit, and assert no `prompt.submit` occurs until the user presses Send. Add tests for insert, edit, send, busy composer, and correct chat scope.
2. **Complete delivery notifications:** implement a deliberate push transport for closed/suspended browsers, or route important events through an existing reliable channel. Add dedupe, quiet hours, event severity and a safe fallback.
3. **Add a critical-only phone-call policy:** invoke `phone_call_me` only for explicitly defined urgent outcomes (for example, a time-sensitive approval or severe failure), with cooldown/deduplication and quiet-hour behavior. Ordinary turn completion should remain a notification, not a call.
4. **Make mobile parity measurable:** run a device acceptance matrix for attachments/camera, voice, approvals, session recovery, PWA installation/share, notifications, and phone-sized layouts against the deployed gateway.
5. **Decide what should remain native-only:** phone sensors/system actions, app lock, launcher shortcuts and Wear OS need a companion app or plugin; do not imply the browser can reproduce Android permissions/background services.
